# 评测说明

评测日期：2026-10-26。统计为本轮固定覆盖集的模拟环境基线，不是线上用户分布，也不是迭代前后对照实验。

## 设计与数据

- 50 个场景：典型 25、边界 15、对抗 10；每个场景在独立进程中生成 2 次，共 100 次。
- 模型调用真实；小红书、天气、酒店、地理编码等外部返回全部使用合成测试数据。
- 规则校验覆盖日期、天数、城市、费用加总等；LLM-as-Judge 根据请求、输出和调用证据进行 0–4 分评审。
- 对不通过结果和关键边界样例进行 AI 复核，修正 6 条评委规则应用错误。没有真人标签，不能计算人机一致率。
- [场景集](evaluation/scenarios.json) 与 [模拟工具数据](evaluation/service-fixtures.json) 随仓库发布。原始响应、调用日志、会话、配置与本机路径记录不发布。

共记录 630 次生成阶段模型 SDK 调用及 100 次评审尝试；100 次行程生成与 100 次评审不能合并写成 200 次行程生成。每个场景只重复 2 次，不能计算 pass^5。

## 主要发现与后续改动

1. 原整程生成的 106 次城市搜索均为第 1 页、每页 20 篇笔记，并只读取前 4 篇详情；长行程未扩大召回范围。这里的 20 是笔记分页大小，不是景点数量。
2. 模拟来源中已返回且可唯一匹配的票价保留率为 395/678，坐标保留率为 437/666。它们衡量证据保留，并非现实准确率。
3. 天气查询失败或超出预报范围时，部分结果仍生成确定天气；生成后的可信度校验仍需完善。
4. 新增的局部修改功能实现双参照周边检索、5→10 公里扩展、未知票价提示、确认应用及撤销，但没有重新运行整套 100 次生成对照，不能声称整体可用率已提升。

## 运行

先配置自己的模型服务。以下命令会调用真实模型，产生费用；工具数据仍为模拟数据。脚本使用 `fcntl`，适用于 macOS / Linux。

```bash
# 在项目根目录；先用少量场景检查配置
backend/.venv/bin/python evals/run_sim_eval.py --run --limit 2 --workers 1
# 批量运行剩余场景
backend/.venv/bin/python evals/run_sim_eval.py --run --limit 100 --workers 2
# 对已有生成结果进行模型评审
backend/.venv/bin/python evals/review_sim_eval.py --review --limit 100
```

输出写入被 Git 忽略的 `evals/sim-100-20261026/`。该目录已有记录会被跳过；如需新实验，应先另行保存旧结果。场景和模拟天气日期固定于本次实验，不应作为真实旅行信息使用。
